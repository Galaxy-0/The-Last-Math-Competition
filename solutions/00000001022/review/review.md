## Semantic audit
The conjecture states a *lower* bound `TC(C) ≥ min(k,n−k)·⌈log₂ q⌉` for any `[n,k]_q` code. As the report explains, `min(k,n−k)·log₂ q` is Wolf's classical **upper** bound on trellis state complexity (the syndrome trellis has at most `q^min(k,n−k)` states per layer); as a lower bound the statement fails badly, because direct-sum codes have tiny minimal trellises. The MacWilliams preamble attaches no hypothesis the bound depends on; the Lean `Conjecture MacW μ := MacW ∧ Clause μ` treats it as an arbitrary conjunct, so refuting the trellis clause refutes the conjunction under any reading of the preamble.

The formalization is faithful to the strongest useful reading. `Clause μ` (Main.lean line 196) quantifies over all `n, k`, all generator sets with `IsGen n k gens` (k length-n generators with `2^k` distinct combinations — exactly a linear `[n,k]₂` code), all `e` with `CeilLog2 2 e` (uniquely `e = 1`), and **every** well-formed trellis `T` representing the code, asserting `2^min(k,n−k)·e ≤ μ.eval T`. Since "log₂ X ≥ B ⟷ 2^B ≤ X" and the trellis complexity of a code is the minimum of the measure over representing trellises, refuting the universal-over-trellises clause automatically refutes every weaker reading (minimum over trellises, minimal/BCJR trellis, minimum over coordinate orders). The trellis definitions (layer sizes, labelled edge sections, root/toor, well-formedness, path labels) are the standard ones and are built from scratch; `mem_labels` proves the enumeration correct.

The counterexample is correct. `C = {00,11}^5 ⊂ F₂^10` is a `[10,5]₂` code (five disjoint-support generators, independent), and the trellis `T10` with layers `1,2,1,2,…,1` and sections `{0→0 (bit 0), 0→1 (bit 1)}` / `{0→0 (bit 0), 1→0 (bit 1)}` represents it: each two-section block forces the two bits equal, and free concatenation gives exactly the 32 codewords — proved in Lean (`ex10_represents`) by exact label-set equality, not heuristics. Its measures are 2, 2, 16, 20, 25, each `< 2^5`, so every log-scale reading of "trellis complexity" (state, edge, total vertex, total edge, Viterbi) is < 5 = the claimed bound. I recomputed the BCJR minimal profile independently (Gaussian ranks: `s_i = rk G_[0,i) + rk G_[i,n) − k` gives `0,1,0,1,…,0`, `s_max = 1 < 5`) — the counterexample is genuine, and the explicit trellis is in fact the minimal one. The whole family `{00,11}^m` is proved for every `m` (not just computed), giving an unbounded gap.

Coverage of alternative readings is unusually careful: minimal-trellis (`clauseMin_false`), coordinate-order minimization (`clausePerm_false`, `clauseMinPerm_false`), worst coordinate order (a second `[4,2]` code `<1000,0111>` checked over all 24 orders in Lean via `worstOrder_false`), rounding (the report correctly notes `⌈log₂20⌉ = ⌈log₂25⌉ = 5` is not < 5 and supplies `m = 6` where `⌈log₂30⌉ = 5 < 6`), q-ary analogues (checked in verify.py for q = 3, 5), and unitless raw totals, where the report honestly identifies raw `|E|` and raw Viterbi count as *not refuted* (they are trivially true for every code) and raw `|V|` as false only for q ≥ 5. Non-vacuity is proved both ways (`rep2_clause_holds`: every trellis for `{00,11}` really needs 2 states; `inter4_meets_bound`: the interleaved `[4,2]` code attains the bound), which rules out the possibility that the formalized clause is trivially unsatisfiable — the hypotheses are instantiated by a real example (`example` at line 662).
