# Disproof of conjecture 00000001022

The conjecture claims that, beyond the MacWilliams identities for support weights, **every
`[n,k]_q` code has trellis complexity at least `min(k, n−k)·⌈log₂ q⌉`**. This is Wolf's classical
*upper* bound `s_max ≤ min(k, n−k)` (in `q`-ary units) turned into a lower bound, and it is false.

The MacWilliams preamble makes no claim that the bound depends on. Even if it is read as a conjunct, the conjunction
is false because the trellis clause is. The clause is claimed for all `q`, so refuting the case
`q = 2` (where `⌈log₂ q⌉ = 1`) is enough.

## Counterexample: `C = {00,11}^5`, a binary `[10,5]` code

`C = {(a₁,a₁,a₂,a₂,…,a₅,a₅)}` is the direct sum of five copies of the repetition code `{00,11}`.
The claimed bound is `min(5,5)·1 = 5` bits.

The trellis below represents `C`: its set of path labels is exactly `C`. It has layer sizes
`1,2,1,2,…,2,1`. At an even time there is one state, and an edge labelled `b` leads to state
`b`. From state `b` the only edge is labelled `b` and returns to the single state.

| measure | value | log₂ | below 5? |
|---|---|---|---|
| max states (state complexity `s_max`) | 2 | 1 | yes |
| max edges per section (edge complexity) | 2 | 1 | yes |
| total vertices `|V|` | 16 | 4 | yes |
| total edges `|E|` | 20 | 4.32 | yes |
| Viterbi operations `2|E|−|V|+1` | 25 | 4.64 | yes |

The minimal (BCJR) trellis has state profile `s_i = k − dim P_i − dim F_i = 0,1,0,1,…,0`, so
`s_max = 1 < 5`. In fact the trellis above *is* the minimal trellis.

**Family.** `{00,11}^m` is a `[2m, m]_2` code with `s_max = 1`, but the claimed bound is `m`.
The trellis has `3m+1` vertices, `4m` edges and `5m` Viterbi operations. It refutes the clause
for state and edge complexity for every `m ≥ 2`, and for all five measures for every `m ≥ 5`.
The smallest instance is `{0000,1100,0011,1111}` (`[4,2]`, `s_max = 1 < 2`).

## Readings covered

- **Measure:** state, edge, total-vertex, total-edge and Viterbi complexity on a log scale, and also raw
  maximum state and edge counts (`2 < 5`).
- **Which trellis:** the minimum over all trellises, or the minimal (BCJR) trellis. One explicit
  trellis bounds every minimum from above, and the BCJR profile is also computed directly.
- **Coordinate order:** the given order, or the minimum over all orders.
- **Worst coordinate order:** this needs another code. The `[4,2]` code generated by `1000, 0111`
  has `s_max = 1 < 2` in *all* 24 orders.
- **Rounding:** floor or ceiling of `log₂`. Rounding up `log₂|E|` and the Viterbi count needs
  `m = 6`, where `⌈log₂ 30⌉ = 5 < 6`.
- **Not refuted:** *unitless raw totals* `|V|`, `|E|` (16 and 20 are at least 5). The bound
  is stated in bits (`⌈log₂ q⌉` bits per symbol), so this is not a natural reading. For `|E|` it
  is also trivially true for every code. The report proves `|E| ≥ n + k·log₂ q`.

**Non-vacuity.** Every trellis for `{00,11}` needs 2 states, so the bound holds for that code.
The interleaved `[4,2]` code `{0000,1010,0101,1111}` attains the bound in its minimal trellis
(profile `0,1,2,1,0`). An exhaustive scan of all binary linear codes of length `n ≤ 6` confirms
Wolf's upper bound for every code, and finds 1785 of the 2825 codes of length 6 below the
claimed lower bound.

## Contents

- `report.tex`, `report.pdf`: the complete argument and the list of readings.
- `lean4/`: a self-contained Lean 4.19.0 project (core library only, no Mathlib).
- `verify.py`: an independent check using only the Python 3 standard library. It uses different
  methods:
  - the BCJR profile from **ranks** of generator submatrices (Gaussian elimination mod `p`),
    cross-checked by counting;
  - the minimal trellis **built** as the pruned syndrome trellis of a parity-check matrix;
  - forward expansion of the explicit trellis;
  - the family for `m ≤ 8`, `q = 3, 5` analogues, and all coordinate orders of the `[4,2]` examples;
  - an exhaustive scan of all binary codes of length `≤ 6`.
- `verification.txt`: a fresh `lake build` log with the axiom report, the forbidden-token scan
  and the output of `verify.py`.

## Lean

These are defined from scratch:

- Codes:
  - words are `List Bool`;
  - `span n gens` lists the `2^k` combinations of the generators;
  - `IsGen n k gens` means `k` independent generators of length `n`.
- Trellises:
  - `Trellis` (layer sizes and sections of labelled edges);
  - `WF` (one root and one toor, edges between adjacent layers, no repeated edge);
  - `IsPath` (a root-to-toor path with a given label sequence);
  - `Represents` (path labels = codewords);
  - `labels` (path enumeration), with the correctness lemma `mem_labels`.
- Measures: `maxStates`, `maxEdges`, `numVertices`, `numEdges`, `viterbiOps`. "`log₂ X ≥ B`" is
  stated as `2^B ≤ X`. `CeilLog2 q e` characterizes `e = ⌈log₂ q⌉`.
- `pastSub`, `futSub`, `minProfile` (the BCJR profile `|C|/(|P_i||F_i|)`), and `permW`,
  `IsPermOf` for coordinate orders.

Main theorems:

- `clause_false : ∀ μ, ¬ Clause μ` and
  **`conjecture_00000001022_false : ∀ MacW μ, ¬ Conjecture MacW μ`**. Here `Clause μ` says: for
  every binary `[n,k]` code and every well-formed trellis representing it,
  `2^(min k (n−k) · ⌈log₂ 2⌉) ≤ μ T`.
- `clauseMin_false` (minimal trellis), `clausePerm_false` and `clauseMinPerm_false` (minimum over
  orders), and `worstOrder_false` (worst order).
- `ex10_*`: the `[10,5]` code is valid, the trellis is well formed and represents it, the values
  are 2, 2, 16, 20, 25, and the BCJR profile is `1,2,1,…,1`.
- The family, proved for **all** `m`:
  - `family_isGen`, `family_wf`, `family_represents`, `family_numbers`, `family_viterbi`;
  - `family_gap_states` (`m ≥ 2`) and `family_gap_all` (`m ≥ 5`);
  - `clause_false_family` and `clause_false_family_all`;
  - `family_minProfile_small` (BCJR maximum 2 for `m ≤ 6`).
- Non-vacuity: `rep2_clause_holds` (every trellis for `{00,11}` has at least 2 states) and
  `inter4_meets_bound`.

The project has no `sorry`, no `native_decide` and no added axioms. `#print axioms` reports at most
`propext`, `Classical.choice` and `Quot.sound`.

**Limitations.**

- Lean treats `q = 2` only, which is enough to refute a claim made for all `q`.
- The theorem that the minimal trellis has `|C|/(|P_i||F_i|)` states is cited, not formalized.
  Lean computes this number, and the explicit trellis gives the upper bound independently.
- The following are in the report only (the first two are also checked in `verify.py`): the
  general-`m` BCJR profile, the `q`-ary remark, and the raw `|E|` inequality.

## 中文说明

猜想断言：在支撑重量的 MacWilliams 恒等式之外，任意 `[n,k]_q` 码的 trellis 复杂度至少为
`min(k, n−k)·⌈log₂ q⌉`。这其实是 Wolf 的**上界** `s_max ≤ min(k, n−k)` 被误写成下界，结论不成立。
MacWilliams 部分只是前言，与该下界无关；即使把它当作合取项，整个合取命题也因下界不成立而为假。
猜想对所有 `q` 断言，只需否定 `q = 2` 的情形（此时 `⌈log₂ q⌉ = 1`）。

**反例**：二元 `[10,5]` 码 `C = {00,11}^5`，即五个长度为 2 的重复码的直和，所断言的下界为 5 比特。
显式 trellis 的层大小为 `1,2,1,2,…,1`，其路径标号集恰为 `C`。各项指标如下：

- 最大状态数 2（状态复杂度 1 比特）；
- 每节最大边数 2；
- 总顶点数 16（log₂ = 4）；
- 总边数 20（log₂ ≈ 4.32）；
- Viterbi 运算数 25（log₂ ≈ 4.64）。

全部小于 5。最小（BCJR）trellis 的状态剖面为 `0,1,0,1,…,0`，`s_max = 1 < 5`。

更一般地，`{00,11}^m` 是 `[2m,m]_2` 码，`s_max = 1`，而断言的下界为 `m`，差距无界。
最小的反例是 `{0000,1100,0011,1111}`。

覆盖的理解：

- 对数尺度下的状态、边、总顶点、总边和 Viterbi 复杂度，以及原始的最大状态数和最大边数；
- 任意 trellis 或最小 trellis；
- 给定坐标顺序或对所有顺序取最小；
- 最坏坐标顺序：由 `1000, 0111` 生成的 `[4,2]` 码在全部 24 种顺序下 `s_max = 1 < 2`；
- 对数取整：向上取整时，总边数和 Viterbi 运算数需用 `m = 6`。

唯一不覆盖的是不带单位的原始总数 `|V|`、`|E|`。下界的单位是比特，这种理解并不自然；
而且对 `|E|` 而言它对任何码都平凡成立（报告中证明了 `|E| ≥ n + k·log₂ q`）。

非空性：`{00,11}` 的任何 trellis 都至少需要 2 个状态，即该码满足此下界；
交错排列的 `[4,2]` 码在最小 trellis 中恰好达到下界。

Lean 4（仅核心库）从零定义了线性码、trellis、路径标号、各复杂度指标、BCJR 剖面和坐标置换，
证明了主定理 `conjecture_00000001022_false`，以及对**所有** `m` 成立的反例族定理。
`verify.py` 用秩计算和校验矩阵构造的 syndrome trellis 独立验证全部结论，
并穷举了长度不超过 6 的全部二元线性码。
